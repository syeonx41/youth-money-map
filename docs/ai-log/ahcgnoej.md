### 2026-11-14 상품 상세 화면
- 역할: ④
- 도구: Claude Code
- 요청: 와이어프레임 화면 11~13(가능 / 가능·전환 필요 / 해당 없음) 기준으로 상품 상세 화면 만들기
- 결과: app/products/[id]/ProductDetail.tsx(조건별 판정·이유·공고 원문, '신청할 때 확인돼요' 조건, 신규 가입 종료 안내, 중복 가입 경고와 갈아타기 순서, 혜택·금리·정부 지원, 신청 일정, 대안 상품, 출처·기준일, 공식 신청처 버튼), app/products/[id]/schedule.ts와 테스트 5개(신청 일정 진행 중·예정·마감, 모두 지나면 '다음 모집 미정'), app/products/[id]/preview(개발용: ⑤ 정답 프로필로 판정한 결과를 상세 화면에 넣어 확인)
- 문제: 결과 화면(③)이 아직 없어 판정 결과(ProductJudgement)를 넘겨받을 방법이 정해지지 않음
- 해결: 상세 화면은 판정 결과를 선택 값으로 받게 만들고, 없으면 상품 정보와 조건 원문만 보여주도록 함. 판정이 들어간 화면은 개발용 미리보기에서 정답 프로필 20개로 확인
- 문제: 브라우저 확장이 연결되지 않아 AI가 화면을 직접 캡처하지 못함
- 해결: 개발 서버에서 상품·프로필 조합 8개를 요청해 응답 코드(없는 상품은 404)와 상황별 문구(전환 필요, 신규 가입 종료, 왜 안 되나요, 대신 이 상품은 어때요 등)가 나오는지 확인

### 2026-11-15 상세 화면 공유 세션 연결, 챗봇 API·화면
- 역할: ④
- 도구: Claude Code
- 요청: ③ PR #8(머지 전)의 공유 세션에 맞춰 상세 화면을 연결하고, API 키가 있다고 가정하고 챗봇 API와 화면까지 한 PR로 만들기
- 결과: 상세 화면이 useJudgeSession()의 판정 결과를 쓰도록 연결하고 ③ 디자인(색·아이콘·상품 그림·경고 문구)에 맞춤(app/products/[id]/). 챗봇 API(app/api/chat/: 요청 검사, 프롬프트 자료, Claude 호출, 인용 원문 대조), 챗봇 화면(app/chat/: 말풍선, 추천 질문, 근거 보기, 개인정보 안내), 테스트 20개(app/api/chat/__tests__, app/chat/__tests__), .env.example 키 이름을 ANTHROPIC_API_KEY 로 변경
- 문제: 공유 세션(useJudgeSession)이 아직 머지 전인 #8에만 있어서, 내 브랜치만으로는 빌드와 화면 확인을 할 수 없음
- 해결: #8 브랜치로 확인용 작업 폴더(git worktree)를 따로 만들고 내 파일만 얹어서 타입 검사, 테스트, 빌드를 확인. ⑤ #9 정답 파일까지 얹으면 테스트 320개 모두 통과. #8 머지 후 최신 main에서 다시 테스트·빌드를 확인하고, Claude in Chrome으로 입력→결과→상세→챗봇 흐름을 직접 눌러 보고 앱 폭 320~430px에서 글자 겹침·잘림이 없는지 측정
- 문제: AI가 공고에 없는 문장을 근거처럼 지어낼 수 있음
- 해결: 답변의 인용(citations)을 서버가 상품 데이터·판정 결과 원문과 대조해서, 원문에 실제로 있는 문장만 화면에 보여주도록 함. 지어낸 인용이 걸러지는지 테스트로 확인
- 문제: 실제 API 키가 없어 Claude를 직접 호출해 보지 못함
- 해결: Claude 호출 부분을 가짜(mock)로 바꾼 테스트로 정상 답변, 거절, 형식 오류, 키 없음(503)을 확인하고, 사용자 입력 원본(생년월일)이 요청에 들어가지 않는지도 확인. 예시 질문 10개 실제 답변 확인은 키 등록 후에 진행
- 보고서 사례 후보: 예
