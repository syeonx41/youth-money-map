### 2026-11-15 첫 화면·조건 입력·결과 화면 구현과 판정 API 연결
- 역할: ③
- 도구: Claude Code (질문으로 설계 정리 → 스펙·티켓 작성 → 티켓별 에이전트 병렬 구현 → 코드 리뷰 2종 → 브라우저 확인)
- 요청: 계획서 와이어프레임(화면 1~9)대로 첫 화면, 입력 5단계, 결과 화면을 만들고 판정 API에 연결
- 결과: app/page.tsx, app/home-buttons.tsx, app/input/(page, steps), app/result/(page, result-card), lib/session/(useJudgeSession, 입력값 변환), lib/result/(결과 화면 모델), lib/home/(기준일), app/layout.tsx(Provider), 테스트 4개 파일
- 문제: 와이어프레임과 데이터가 맞지 않았어요. 가구원 수 입력이 없어 중위소득 판정을 할 수 없었고, 가입 상품의 "없음/모름"이 한 칸이라 엔진의 없음([])과 모름(null)을 구분할 수 없었어요.
- 해결: 가구원 수 질문을 추가하고(1인 가구는 자동 1명) "없어요"와 "잘 모르겠어요"를 나눴어요. 정답 프로필 20개를 모두 화면 선택만으로 넣을 수 있는지 테스트로 확인했어요.
- 문제: AI가 설계 질문을 마친 뒤 스펙·티켓 없이 바로 코드를 쓰기 시작했어요.
- 해결: 사람이 멈추게 하고, 만든 코드를 지운 뒤 스펙(사용자 스토리 52개)과 티켓 6개를 먼저 쓰고 다시 구현했어요.
- 문제: 코드 리뷰에서 미래 생년월일(예: 20300101)이 통과돼 "만 -4세"로 모든 상품이 '해당 없음'이 되는 버그, 오류 뒤 "이전"이 5단계로 가는 버그, 실패 알림이 앞 단계에 남는 버그가 나왔어요.
- 해결: 고친 뒤 테스트를 추가하고, 로컬 브라우저에서 정답 프로필 P02·P08을 직접 입력해 정답표와 같은지 확인했어요.
- 문제: 엔진의 중복 가입 경고 문구에 조사 오류("청년도약계좌과")가 있었어요.
- 해결: 결과 화면은 같은 뜻의 문구를 조사를 맞춰 따로 만들고, 엔진 문구는 ①에 알리기로 했어요.

### 2026-11-15 첫 화면·입력·결과 화면 디자인 다듬기 (지도, 아이콘)
- 역할: ③
- 도구: Claude Code (frontend-design 스킬, 브라우저로 화면 확인)
- 요청: 지역 선택에 지도 느낌을 넣고, 이모지·특수문자 대신 깔끔한 SVG 아이콘으로 바꾸고, 결과 카드의 "? 조건 → 모름" 표시와 전체 디자인을 다듬기
- 결과: 색·글꼴 토큰(app/globals.css, app/layout.tsx), 선 아이콘 모음·시도 지도·상품 그림 타일(app/ui/), 첫 화면(app/page.tsx, app/home-buttons.tsx), 입력 5단계(app/input/), 결과 화면·카드(app/result/). 판정 로직과 결과 화면 모델은 바꾸지 않았어요.
- 문제: 정부 디자인 시스템(KRDS) 아이콘을 쓰려 했지만 저장소와 누리집에서 이용 조건(공공누리 유형)을 확인하지 못했고, 아이콘 91개가 대부분 공통 UI용이라 주택·적금 같은 그림이 없었어요.
- 해결: 확인하지 못한 에셋은 넣지 않고, 아이콘은 직접 그린 SVG로 만들었어요. 지도는 통계청 2018 시·도 경계(southkorea-maps, "Free to share or remix")를 단순화해서 썼고 출처를 파일 머리말에 적었어요.
- 문제: 지도에서 서울·광주 같은 시 지역이 너무 작아 누르기 어렵고, 울릉도·독도까지 넣으면 본토가 왼쪽으로 치우쳤어요.
- 해결: 시 지역은 점으로 표시하고 누르는 범위를 넓혔고, 지도 아래에 같은 값을 고르는 버튼을 함께 뒀어요. 울릉도·독도는 동해 쪽 작은 상자에 따로 그렸어요.

### 2026-11-15 입력·결과 화면 문구 다듬기 (병역필 등)
- 역할: ③
- 도구: Claude Code
- 요청: "병역 다녀왔어요" 같은 어색한 표현을 "병역필"처럼 다듬고 화면 문구 전반 확인
- 결과: 병역 항목을 "병역 사항 / 병역필·해당 없음·모름"으로, 대화체 선택지(혼자 살아요, 결혼했어요, 없어요 등)를 명사형(1인 가구, 기혼 또는 결혼 예정, 가입한 상품 없음 등)으로, 주택 질문을 무주택·보유 / 세대주·세대원으로 바꿨어요. 입력칸 오른쪽 단위와 겹치던 라벨 괄호(만원·명·개월)를 빼고, 결과 카드·오류 안내 문구를 정리했어요. (app/input/, app/result/, app/page.tsx, lib/session/input-draft.ts) 선택값(value)과 판정 로직은 그대로예요.
- 문제: 처음에 취업 상태를 "중소기업 재직자·자영업자"로 바꿨는데, Chrome에서 결과 화면을 확인해 보니 판정 엔진의 해당 없음 이유 문구는 "중소기업 재직·자영업"이라 입력 화면과 표현이 어긋났어요.
- 해결: 엔진 문구(① 담당)에 맞춰 입력 선택지를 "중소기업 재직·자영업·학생·취준생"으로 되돌렸어요. 같은 테스트에서 병역필 버튼과 복무 기간 라벨이 붙어 보이는 것도 간격을 넣어 고쳤어요.
