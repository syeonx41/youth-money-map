## 3. 주요 개발 결과

개발계획서 '5. 상세 기능'(필수 5개, 선택 2개) 기준이에요.

| | 핵심 기능 | 구현 상태 | 실제 구현 결과 / 변경 사항 |
|---|---|---|---|
| ① | 조건 입력 (필수) | ■ 완료 □ 일부 □ 미구현 | · 나이(생년월일·지역·병역) → 소득(연소득·취업 상태) → 가구(형태·가구원 수·가구 소득) → 주택(본인 명의 주택·세대주·거주 형태) → 가입 중인 상품의 5단계 입력. 생년월일만 필수이고 나머지는 모두 '모름' 선택 가능<br>· 입력값은 화면 메모리에만 두고 서버·브라우저에 저장하지 않음<br>· 변경: 주거래 은행 입력은 우대금리 계산을 구현하지 못해 제외. 중위소득 판정을 위해 가구원 수를 추가하고, 가입 상품의 '없음'과 '모름'을 나눔. 지역은 시·도 지도와 버튼으로 선택 |
| ② | 맞춤 판정 + 이유 표시 (필수) | ■ 완료 □ 일부 □ 미구현 | · 상품 7개(대출 3, 적금 2, 청약·주거 2)의 조건표(JSON)와 입력값을 규칙 엔진으로 비교해 조건마다 충족 / 미충족 / 확인 필요와 이유 문구, 공고 원문을 표시<br>· 완료 기준(샘플 프로필 5개 이상 일치) → 공고 기준 정답 프로필 20개 모두 일치(배포 사이트 포함)<br>· 추가: 신규 가입 종료 상품 처리, 중위소득 상·하한, 병역 기간 차감, 입력받지 않는 조건(순자산 등)은 '신청할 때 확인돼요'로 안내 |
| ③ | 탭별 결과 비교 (필수) | ■ 완료 □ 일부 □ 미구현 | · 대출 / 적금 / 청약·주거 탭에 카드 목록. 가능 → 확인 필요 → 해당 없음 순으로 정렬하고, 상태 칩으로 걸러 보기, 입력 조건 요약 줄 표시<br>· 카드마다 판정 배지, 충족한 조건, 혜택 요약, 해당 없음 이유 표시<br>· 변경: '받을 수 있는 정부지원금 / 챙길 수 있는 우대금리' 합산 요약과 금리순·정부지원 많은순 정렬은 금리 계산 기능을 구현하지 못해 제외 |
| ④ | AI 챗봇 (상품 Q&A) (필수) | ■ 완료 □ 일부 □ 미구현 | · 보고 있는 상품의 판정 결과와 공고 원문만 생성형 AI(Google Gemini)에 넘겨 쉬운 말로 답변. 사용자 입력 원본(생년월일 등)은 보내지 않고, 자격은 다시 판단하지 않음<br>· 서버가 답변의 인용을 원문과 대조해 실제로 있는 문장만 '근거'로 표시. 추천 질문, 개인정보 입력 금지 안내<br>· 예시 질문 10개를 배포 사이트에서 확인: 통과 6, 부분 통과 4, 실패 0(금지된 답변 0)<br>· 변경: AI API 비용 지원이 없어 Gemini 무료 키로 연결 |
| ⑤ | 공식 신청처 연결 (필수) | ■ 완료 □ 일부 □ 미구현 | · 상품 상세에 공식 신청처 이동 버튼, 공고 출처 링크, 정보 기준일 표시<br>· 상품 7개의 신청처·출처 링크 12개 모두 정상 접속 확인(2026-11-16) |
| ⑥ | 중복 가입 체크 (선택) | ■ 완료 □ 일부 □ 미구현 | · 가입 중인 상품과 동시 가입 제한 규칙을 비교해 결과 화면에 경고 띠와 '가능 · 전환 필요' 배지 표시. 가입 여부를 '모름'으로 두면 '가입 중이라면 동시 가입 불가' 확인 안내<br>· 상품 상세에 갈아타기 순서와 '먼저 해지하지 말 것' 안내(예: 청년도약계좌 → 청년미래적금)<br>· 변경: 유지 vs 전환 비교(금리·정부지원금·만기 예상액)는 계산 기능을 구현하지 못해 제외 |
| ⑦ | 신청 일정 안내 (선택) | ■ 완료 □ 일부 □ 미구현 | · 상품 상세에 회차별 신청 기간과 진행 중 / 마감 / 다음 모집 미정 표시 |

| AI 활용 방법 | · 작업 규칙(AGENTS.md)을 만들어 모든 AI 도구가 같은 원칙(판정은 코드로만, 입력값 저장 금지, 조건마다 공고 원문)을 따르게 하고, 작업이 끝날 때마다 AI 활용 기록(docs/ai-log)을 자동으로 남기게 함<br>· ① 판정 엔진·API·테스트 코드 작성, 경계값 오류(중위소득 150.01%) 수정<br>· ② 공고 조사와 조건표 작성 후, AI가 옮긴 원문을 대조 스크립트로 공식 PDF·페이지와 글자 단위로 대조(141개 조각)해 따옴표·띄어쓰기 차이까지 고침<br>· ③ AI와 질문으로 설계를 정리한 뒤 스펙(사용자 스토리 52개)·티켓을 먼저 쓰고 구현. AI 코드 리뷰로 미래 생년월일 입력 버그 등을 찾아 고침<br>· ④ 상품 상세·챗봇 API 구현. AI가 근거를 지어내지 못하게 인용을 원문과 대조하는 장치를 넣고, 모델별 응답 시간을 재서 모델을 고름<br>· ⑤ 공고 기준 정답 프로필 20개와 챗봇 예시 질문 작성. 데이터·엔진과 따로 만든 정답으로 교차 검증하고, 배포 사이트에서 판정 API·화면·챗봇을 자동·수동으로 점검 |

팀원별 AI 활용 기록 전체는 [docs/ai-log](./ai-log/)에 있어요.

## 5. 개발 과정의 어려움 및 해결 방법

### 사례 1. 공고와 다르게 판정되는 경계 칸을 정답 프로필로 찾아 고침

| 구분 | 내용 |
|---|---|
| 문제 상황 | · 공고 기준으로 만든 정답 프로필 20개를 판정 엔진으로 돌리자 3칸이 정답과 달랐음<br>· ① 신규 가입이 끝난 청년도약계좌가 '가능'으로 나옴 ② 서울 청년월세의 소득 하한(기준 중위소득 48% 초과)을 넣을 필드가 없어 소득 39%도 '가능'으로 나옴 ③ 중위소득 150.01%를 반올림(150.0%)한 뒤 비교해 '150% 이하 충족'으로 잘못 판정 |
| 시도한 방법 | · 틀린 칸을 실패로 두지 않고 '보류'로 표시해 테스트를 유지하면서, 원인을 엔진·데이터·정답 오류로 나눠 담당에게 공유<br>· ①이 신규 가입 종료·소득 하한 필드를 추가하고 비교를 반올림 전 값으로 바꿈 → ②가 데이터에 반영 → ⑤가 보류 칸을 정답으로 옮김<br>· 데이터(②), 데이터를 보지 않고 공고만으로 만든 검증 정답(②), 정답 프로필(⑤)을 따로 만들어 서로 대조 |
| 최종 결과 | ■ 해결 □ 일부 해결 □ 미구현 |
| 문제 발생 사유 및 배운 점 | · 처음 데이터 형식이 공고의 예외 규칙(판매 종료, 소득 하한)을 담지 못했고, 화면 표시용 반올림을 비교에도 써서 생긴 문제였음<br>· 경계값 정답을 먼저 만들어 두면 AI가 만든 코드의 작은 오류도 숫자로 잡을 수 있고, 비교는 원래 값으로 하고 반올림은 표시에만 써야 한다는 것을 배움. 수정 후 자동 테스트와 배포 사이트 20개 프로필 모두 정답과 일치 |

### 사례 2. AI가 근거를 지어내거나 빠뜨리는 문제를 원문 대조와 기준 점검으로 줄임

| 구분 | 내용 |
|---|---|
| 문제 상황 | · AI가 공고를 옮길 때 따옴표·띄어쓰기가 바뀌거나 떨어진 문장을 이어 붙였고, 저장했다는 원문 파일이 실제로는 없던 경우도 있었음<br>· 챗봇은 원문에 없는 문장을 근거처럼 만들 위험이 있었고, 첫 실행에서는 판정 이유의 숫자 등 꼭 필요한 내용을 빠뜨림. 처음 고른 무료 모델은 50초 넘게 걸려 시간 초과가 남 |
| 시도한 방법 | · ② 공식 PDF·페이지를 직접 내려받아 원문 141개 조각을 스크립트로 글자 단위 대조하고, 문장마다 출처 쪽수를 표시<br>· ④ 서버가 챗봇 답변의 인용을 원문과 대조해 실제 있는 문장만 근거로 보여주게 하고, 답변 규칙에 빠진 항목을 추가. 모델별 응답 시간을 재서 2초 안에 답하는 모델로 바꿈<br>· ⑤ 예시 질문 10개를 '꼭 들어가야 할 것 / 하면 안 되는 것' 기준으로 배포 사이트에서 점검 |
| 최종 결과 | □ 해결 ■ 일부 해결 □ 미구현 |
| 문제 발생 사유 및 배운 점 | · 생성형 AI는 그럴듯한 문장을 만들 수 있어서, 근거는 사람이 원문으로 확인하고 서버에서 한 번 더 걸러야 함<br>· 금지된 답변은 0개가 됐지만 4개 질문은 데이터에 있는 핵심 수치(한도·기간·신청 방법)가 답변에서 빠져 '부분 통과'로 남음. AI 결과물은 기준을 미리 정해 두고 같은 기준으로 반복 점검해야 품질을 관리할 수 있다는 것을 배움 |

| 점검 항목 | 주요 내용 |

| 작동 테스트 방법 | · 자동 테스트(Vitest) 323개 모두 통과: 판정 엔진, 상품 데이터 형식, 정답 프로필 20개, 입력값 변환, 결과 화면 모델, 챗봇 API(가짜 AI로 정상·거절·시간 초과·키 없음)<br>· 정답 프로필 20개(나이·소득·병역·중위소득 경계, '모름', 가입 중인 상품 등): 배포 사이트 판정 API와 실제 화면(모바일 폭)에서 1~5단계를 직접 입력해 결과 비교 → 20개 모두 정답과 일치<br>· 챗봇 예시 질문 10개: 배포 사이트에서 '꼭 들어가야 할 것 / 하면 안 되는 것' 기준으로 확인 → 통과 6, 부분 통과 4, 실패 0<br>· 상품 7개의 공식 신청처·출처 링크 12개 접속 확인 → 모두 정상 |
| 발견된 오류 및 제약 | · 개발 중 발견해 고친 오류: 중위소득 반올림 후 비교(150.01%), 신규 가입 종료 상품의 '가능' 표시, 미래 생년월일 입력 시 '만 -4세' 판정, 오류 안내 뒤 '이전' 버튼 이동, 중복 가입 경고 문구 조사 오류('청년도약계좌과', PR #12에서 수정), 챗봇 응답 시간 초과(모델 변경)<br>· 남은 제약: 버팀목 병역 연장(중소·중견기업 취업자)과 청년미래적금 맞벌이 2인 가구 기준 완화는 현재 입력값으로 표현할 수 없음. 서울 청년월세 제대군인 연령 연장은 근사값이라 복무 1~3년 일부는 실제와 다를 수 있음<br>· 순자산·보증금·면적처럼 입력받지 않는 조건은 '신청할 때 확인'으로 안내만 함. 상품은 7개이고, 공고가 바뀌면 데이터를 직접 고쳐야 함 |
| 향후 개선 사항 | · 금리·정부지원금 계산(우대 조건별 금리, 만기 예상 수령액, 유지 vs 전환 비교)과 결과 화면 금리순 정렬<br>· 신청 일정 모아보기 화면(D-day)과 캘린더 저장<br>· 공공 API 연동으로 상품 확대와 공고 변경 자동 반영<br>· 부부합산 소득·재직 기간 등 입력 항목을 늘려 판정 정확도 향상<br>· 챗봇 답변 규칙 보완(질문 주제의 핵심 수치 포함) 후 예시 질문 재점검 |
